Live-M.

A lightweight terminal system monitor that replaces htop and psensors — and only looks at processes when you ask it to.

Per-core CPU, memory, swap, disks, temperatures and live Wi-Fi throughput in one calm, colour-coded view. Press p when you want to see the five busiest processes. Everything updates in place, so you can leave it open on a second monitor and forget about it.

What it shows

Everything that matters.
Nothing that doesn't.

Live-M is deliberately not a process explorer. It answers one question well: how is this machine doing right now? And when the answer is “busy”, one key shows what is busy.

Per-core CPU

Colour-coded usage bars for every core, two columns on wide terminals, plus the overall average and 1/5/15-minute load.

RAM and swap

Used and total memory in GiB with a clear percentage bar for each, so pressure is obvious at a glance.

Real disks only

Every real mountpoint gets a bar. tmpfs, snap mounts and /boot are filtered out instead of cluttering the panel.

Temperatures

CPU package on a full-width bar, per-core temperatures underneath, and any other detected sensor that reports useful data.

Live Wi-Fi speed

Current download and upload throughput sit in the header, next to the hostname, without taking over the screen. The wireless interface is detected from the kernel, whatever it is called.

Lighter than htop

By default Live-M skips /proc/[pid] entirely and uses around 0.4% of one core, which is the whole reason it exists.

Top processes on demand

Press p for the five busiest processes by CPU and by RAM. It is off by default, sampled every 3 seconds and only while it is on screen, so the cost is small and only paid when you ask.

Your terminal stays intact

Live-M runs on the alternate screen. When you quit with q or Ctrl+C, the shell output from before you started it is right where you left it.

Any Linux

Pure Python on /proc and /sys, so it is not tied to a distribution or CPU architecture. Ready-made packages for Debian, Ubuntu, Mint and Arch; Python 3.10 or newer.

Why this exists

Small on purpose.

htop walks every process in /proc/[pid]/ on every refresh. That is useful when you need a process list — and unnecessary weight when you only want the health of the machine.

By default Live-M does not iterate over processes at all. The result is a monitor that stays around 0.4% CPU, starts instantly and looks good doing it. When you do want to know what is loading the machine, press p: the panel reads one small file per process, samples every 3 seconds and is not sampled at all while hidden. Measured with 300 processes, that is about 0.8% CPU in total.

  • Live-updating panels, no flicker
  • Refresh interval adjustable with + and -
  • Top processes with p, or start with them on using --procs
  • Optional --interval, --no-color, --version and --help
  • Quit with q or Ctrl+C

Install Live-M.

Packaged for Debian, Ubuntu and Linux Mint, with an Arch Linux package below. Install it from the signed Icenux repository and updates arrive with apt upgrade. The package is small, the dependency list is one package long, and the binary is on your PATH immediately.
